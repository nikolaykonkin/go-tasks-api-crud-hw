## Требования

- Go 1.21 или выше
- `curl` для тестирования (или Postman)

## Запуск

```bash
git clone <ссылка на ваш репозиторий>
cd <название вашего репозитория>
go run cmd/server/main.go
```

После запуска в консоли появится:
```
server listening on :8080
```

Сервер слушает `http://localhost:8080`. Дальше можно тестировать эндпоинты через `curl` — примеры ниже или в [manual-tests.md](manual-tests.md).

Для сборки бинарника (имя `-o server` — название итогового исполняемого файла, можно указать любое):
```bash
go build -o server ./cmd/server
./server
```

## Эндпоинты API

| Метод  | Путь          | Описание                    | Тело запроса                       | Успешный код | Ошибки          |
| ------ | ------------- | ---------------------------- | ----------------------------------- | ------------ | --------------- |
| GET    | `/tasks`      | Получить список всех задач   | —                                    | 200          | —                |
| POST   | `/tasks`      | Создать новую задачу         | `{"title": "...", "done": false}`   | 201          | 400              |
| GET    | `/tasks/{id}` | Получить задачу по ID        | —                                    | 200          | 404              |
| PUT    | `/tasks/{id}` | Обновить задачу целиком      | `{"title": "...", "done": true}`    | 200          | 400, 404         |
| DELETE | `/tasks/{id}` | Удалить задачу                | —                                    | 204          | 404              |
| GET    | `/health`     | Проверка состояния сервиса   | —                                    | 200          | —                |

Все ответы (включая ошибки) — в формате JSON с заголовком `Content-Type: application/json`. При обращении к `/tasks` или `/tasks/{id}` неподдерживаемым методом сервис отвечает `405 Method Not Allowed`.

## Формат данных

```json
{
  "id": 1,
  "title": "Купить молоко",
  "done": false,
  "created_at": "2026-08-14T10:30:00Z"
}
```

- `id` — генерируется на сервере, любой `id`, присланный клиентом в теле запроса, игнорируется.
- `title` — обязательное поле, не может быть пустым или состоять только из пробелов.
- `done` — статус выполнения, по умолчанию `false`.
- `created_at` — дата создания в формате ISO8601 (RFC3339), проставляется автоматически при создании и не меняется при `PUT`.

## Формат ошибок

Единый формат для всех ошибок:

```json
{ "error": "сообщение об ошибке" }
```

| Код | Когда возвращается |
| --- | --- |
| 400 | Некорректный JSON в теле запроса, пустой `title`, невалидный `id` в пути |
| 404 | Задача с указанным `id` не найдена |
| 405 | Метод не поддерживается для данного пути |
| 500 | Внутренняя ошибка сервера |

## Примеры запросов

### Создать задачу

```bash
curl -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "Купить молоко"}'
```
```json
{"id":1,"title":"Купить молоко","done":false,"created_at":"2026-08-14T10:30:00Z"}
```

### Получить список задач

```bash
curl http://localhost:8080/tasks
```
```json
[{"id":1,"title":"Купить молоко","done":false,"created_at":"2026-08-14T10:30:00Z"}]
```

### Получить задачу по ID

```bash
curl http://localhost:8080/tasks/1
```
```json
{"id":1,"title":"Купить молоко","done":false,"created_at":"2026-08-14T10:30:00Z"}
```

### Обновить задачу

```bash
curl -X PUT http://localhost:8080/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"title": "Купить молоко и хлеб", "done": true}'
```
```json
{"id":1,"title":"Купить молоко и хлеб","done":true,"created_at":"2026-08-14T10:30:00Z"}
```

### Удалить задачу

```bash
curl -i -X DELETE http://localhost:8080/tasks/1
```
```
HTTP/1.1 204 No Content
```

### Health-check

```bash
curl http://localhost:8080/health
```
```json
{"status":"ok"}
```

Полный набор сценариев с ошибочными запросами — в [manual-tests.md](manual-tests.md).

## Архитектурные решения

- **Слоистая структура** (`cmd` / `internal/handlers` / `internal/models` / `internal/storage`) отделяет точку входа, HTTP-логику, модель данных и хранилище друг от друга.
- **Интерфейс `Storage`** в `internal/storage/storage.go` позволяет заменить in-memory реализацию на БД в будущем, не трогая обработчики — `Handler` зависит от интерфейса, а не от конкретной структуры.
- **Потокобезопасность**: `MemoryStorage` защищён `sync.RWMutex` — операции чтения (`List`, `Get`) используют `RLock` и могут выполняться параллельно, операции записи (`Create`, `Update`, `Delete`) используют эксклюзивный `Lock`.
- **Единый формат ошибок** (`{"error": "..."}`) реализован через общие вспомогательные функции `writeJSON`/`writeError` в `handlers/tasks.go`, чтобы не дублировать логику формирования ответа в каждом обработчике.
- **Логирование запросов** реализовано как HTTP middleware (`internal/middleware/middleware.go`), оборачивающий весь `http.ServeMux` — логируется метод, путь и время выполнения каждого запроса.
- **Генерация ID и `created_at`** происходит только на сервере — `Create` и `Update` в `MemoryStorage` игнорируют/перезаписывают эти поля, даже если клиент прислал их в теле запроса, что исключает подмену ID или даты создания клиентом.
